# Plan: 予定表画像を縦1列に戻し、スマホ1画面に1か月が収まる縦長にする

Issue: [#215](https://github.com/kchan-lab/hoopo/issues/215)
設計の正: `docs/REQUIREMENTS.md` §6(予定表画像)、`docs/DESIGN_GUIDELINES.md`
前回: [#204](https://github.com/kchan-lab/hoopo/issues/204) / [schedule-image-layout/plan.md](../schedule-image-layout/plan.md)

## 目的

#204 では「1か月を1画面で見渡す」を「ほぼ正方形(1152×1216)の2カラム」と解釈したが、
利用者の意図は **iPhone 16 程度のスマホで、1行1日の縦1列のまま1か月すべてが1画面に見える** ことだった。
正方形は縦長の画面では上下が余り、文字が小さく見える。縦1列に戻し、画面比率に収まる範囲で文字を最大化する。

## 方針

```
┌──────────────────────────────┐  幅 1080
│ SKC粉浜・北粉浜ミニバスケットボール │  ヘッダー(薄く)
│ 2026年10月 練習予定               │
├──────────────────────────────┤
│  1 木                            │
│  2 金                            │
│  3 土  9:00–13:00   北粉浜小学校   │  1日1行 × 日数
│  …                               │  行の高さは固定
│ 31 土  9:00–13:00   北粉浜小学校   │
├──────────────────────────────┤
│                  powered by hoopo │
└──────────────────────────────┘
      31日の月で高さ ≦ 2160(1:2.0)
```

### 設計判断

1. **縦横比の上限を 1:2.0 に置く**: iPhone 16 の画面は 393×852pt(1:2.17)。LINE の全画面表示では
   上下にバーが重なるため、1:2.0 以内なら拡大せずに全体が収まる。修正前(720×1524 = 1:2.1)は
   形は近かったがわずかにはみ出し、文字も小さかった(時間・場所 16px = 画面上 約9pt)。

2. **幅は 1080px**: 縦横比だけが見え方を決めるので幅は解像度の問題。iPhone の物理解像度(幅 1179px)に
   近い 1080 にして、全画面表示で拡大されてもにじまないようにする。1MB 上限は実測で確認する。

3. **行の高さは固定(同じ日に複数コマあっても伸ばさない)**: 行を伸ばすと 1:2.0 を保証できない。
   複数コマの日は同じ行の中に縦に積み、その日だけ文字を小さくする。
   高さは `ヘッダー + 日数 × 行 + フッター` の単純な式になり、rows の中身に依存しなくなる。
   退けた案: 複数コマを横に並べる(1080 幅では時間+場所が2組入らない)、
   行を伸ばして全体を縮める(日によって文字サイズがばらつき、計算も複雑になる)。

4. **余りはすべて文字サイズに回す**: 31日の月で 1:2.0 に収まる行の高さを先に決め、
   文字は行の高さに対する比率で決める。ヘッダー・フッターは行に高さを譲るため薄くする。
   最終値は実画像を iPhone 16 相当の表示サイズに縮めて目視で詰める。

5. **2カラム用の関数は削除する**: `splitScheduleColumns` / `scheduleColumnHeight` / `SCHEDULE_COLUMN_COUNT`
   は利用箇所がなくなる。`scheduleImageHeight(rows)` のシグネチャは残し(route.ts はそのまま)、中身を単純化する。
   `SCHEDULE_ENTRY_LINE_HEIGHT` は「複数コマ時の1件の高さ」として意味が変わるので付け直す。

6. **色・書体・トークンは変えない**(#204 と同じ。配置と寸法だけ)。

7. **`docs/REQUIREMENTS.md` §6 を実装より先に更新する**(2カラムの記述を置き換える)。
