# Plan: E2E の並列衝突をなくす

Issue: [#175](https://github.com/kchan-lab/hoopo/issues/175)
設計の正: docs/DEVELOPMENT.md テスト戦略 / `playwright.config.ts`

## 目的

全体 E2E を並列で回すと、毎回ちがう 1〜2 件が落ちていた。CI は `retries: 1` で吸収していたため
赤くはならないが、本当の不具合と区別がつかず、落ちるたびに調査が必要だった。
リトライに頼らずに結果を信用できる状態にする。

## 調べて分かったこと(2026-09-19)

原因は2つあった。

1. **月の衝突(本命)**。各スペックが「2031〜2090 年のランダムな月」を使っていたが、
   1回の実行で 19 か所 × 2 プロジェクト = 最大 38 回引くのに対し候補は 720 通りしかない。
   誕生日のパラドックスで **1回あたり平均 1 件ほど衝突**する(38×37/2/720 ≈ 0.98)。
   症状(毎回ちがう 1〜2 件が落ちる)と一致する。
2. **開発サーバーの劣化**。portal / admin の Next dev を長く動かしたまま回すと遅くなり、
   待ち時間切れが増える。実測で 1 回目 2 件 → 2 回目 7 件 → 3 回目 10 件と増え、
   コンテナを再起動すると 1 件に戻り、実行時間も 2 分 6 秒 → 47 秒になった。

## 方針

```
uniqueMonth() を e2e/unique-month.ts に1つだけ置き、各スペックの同名関数を消す

  年 = 2031 + ワーカー番号 × 12 + そのワーカー内で呼ばれた回数
  月 = 06 固定
```

### 設計判断

1. **テストごとに別の「年」を割り当てる**(連番の月にしない)。前の月・次の月へ動いて
   「練習はまだ登録されていません」を確かめるテストがあるため、隣の月まで空いている必要がある。
   月を連番で配ると隣を別のテストが使ってしまい、**決定的に落ちる**(実測済み)。
2. **ワーカーごとに年の帯を分ける**。ワーカーは別プロセスなので、カウンタだけでは重なる。
   ワーカー番号を帯の起点にすれば、1回の実行のなかで必ず別の年になる。
3. **ランダムをやめる**。ランダムは「たまに落ちる」を生み、再現もできない。
   決定的に割り当てれば衝突は構造的に起きない。
4. **CI の `retries` は 1 のまま残す**。衝突は無くなったが、CI は毎回まっさらなコンテナで
   初回コンパイルが走るぶん遅く、コールドスタート由来の失敗はありうる。
   ここを 0 にするのは、CI 側で数回グリーンを重ねてから判断する。
5. **サーバー劣化は手順で回す**。ローカルで全体 E2E を回す前に portal / admin を再起動する、
   と docs に書く。CI は毎回新しいコンテナなので影響を受けない。

## 完了条件

- 全体 E2E を並列で 3 回連続実行して、リトライなしで全通過する(実測: 113 passed × 3)
- 月の決め方と、隣の月まで空ける理由が `e2e/unique-month.ts` に残っている
- ローカルで回す前にサーバーを再起動する手順が docs/DEVELOPMENT.md にある
