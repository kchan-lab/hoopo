# Plan: 初回登録に確認画面(③)を挟む

Issue: [#157](https://github.com/kchan-lab/hoopo/issues/157)
設計の正: docs/REQUIREMENTS.md §3(初回登録)・§4.2-2(初回登録画面)/ CLAUDE.md 絶対原則 2
関連プラン: child-registration(登録フローの原型)/ child-birthdate-height・child-name-split(登録項目を増やした 2 件)

## 目的

初回登録が「①子ども情報 → ②参加情報 → 登録完了」で、送信前に内容を見直す機会がない。
child-birthdate-height(生年月日・身長)と child-name-split(姓 / 名 とそれぞれのよみ)で
入力項目が 8 項目まで増え、打ち間違いに気づかないまま登録が確定してしまう。
送信の直前に **確認画面(③)** を挟み、「この内容で登録する」を押して初めて POST する。
承認者の要望(2026-09-15)。

## 方針

```
[前]  ①子ども情報 ──「次へ」──▶ ②参加情報 ──「登録を完了する」──▶ POST /api/children
[後]  ①子ども情報 ──「次へ」──▶ ②参加情報 ──「確認へ進む」──▶ ③確認 ──「この内容で登録する」──▶ POST
                    ◀──「①を修正」(お子さんの欄)──┘          ◀──「修正する」/ 見出しの ‹ ──┘
```

- 見出しは `1/3` `2/3` `3/3`。③のタイトルは「入力内容の確認」
- ③の中身: お子さんごとに お名前(漢字のフルネーム)/ よみ / 呼び名 / 生年月日 / 学年 / 身長 / 性別、
  続けて「参加について」として 参加できる曜日 / 時間帯 / 続柄 / コーチへの伝達事項
- 任意項目(呼び名・伝達事項)が空なら「未入力」と出す
- 送信は③からだけ。②の CTA は「確認へ進む」に変える
- 家族連携(招待コード)は 1 画面 1 項目なので確認画面を挟まない

### 設計判断

1. **確認画面を挟む(操作が 1 タップ増える)**: CLAUDE.md 絶対原則 2(保護者の操作負担を最小に)と
   正面からぶつかるが、**登録は一度きり**であり、増える負担は生涯 1 タップ。一方で間違えたまま
   登録されると、保護者が家族の設定を開いて直すか、コーチに連絡して直してもらうことになり、
   修正のコストのほうが明らかに大きい(名前の誤りは名簿・出欠・月謝・編成のすべてに出る)。
   タップ 1 回と修正コストを比べて、確認画面を採る。
   退けた案: ②の CTA の直前に入力内容のサマリを畳んで置く(②が縦に長くなり、
   スマホでは結局スクロールが必要で「見直した」感が出ない)。
2. **①へ戻る導線は「お子さんの欄の『①を修正』」、見出しの ‹ は②へ**: iOS の慣習どおり
   見出しの戻る矢印は「1 つ前の画面」= ②に戻す。①の内容(子ども情報)を直したいときは、
   直したいお子さんの欄の右肩にある「①を修正」から直接①へ跳ぶ。
   「どこを直したいか」から入れるほうが、戻る矢印を 2 回押させるより短い。
   退けた案: 見出しの ‹ を①に戻す(②を飛ばすことになり、戻る矢印の意味が画面ごとに変わる)。
3. **入力の state は step を切り替えるだけで保持する**(既存の作りを変えない): ①②③は同じ
   コンポーネントの表示切替で、`kids` / `weekdays` / `startTime` / `endTime` / `relation` /
   `coachNote` はそのまま残る。localStorage は使わない(CLAUDE.md してはいけないこと)。
4. **検証の位置はそのまま**: ①→② で子ども情報、②→③ で 曜日・続柄 を検証する。
   ③ではすでに検証済みの値しか出ないので、③は表示と送信だけを担う
   (念のため③の送信時にも曜日・続柄を確認し、欠けていたら②へ戻す)。検証の正はサーバー。
5. **新しいデザイン言語を作らない**: 確認画面は家族の設定の「お子さんの情報」と同じ
   `.label` + `ul.news > li.row`(項目名を左、値を右)で組む。保護者が別画面ですでに見ている
   見た目と同じになり、CSS の追加は伝達事項の改行を保つ `.news .row .val` だけで済む。
6. **学年は `GradeHint` を使う**: `gradeFromBirthDate`(`@hoopo/api/grade-shared`)を内部で呼ぶ
   既存コンポーネントで、①の入力欄の下に出るのと同じ「小学N年生」のピルがそのまま出る。
   文言の重複を作らない(学年の正はサーバーが同じ純関数で算出する)。
7. **「未入力」は文字で示す**(色に頼らない): 家族の設定と同じ `未入力` の 2 文字。
   DESIGN_GUIDELINES の「色だけに頼らない」に従う。

## 完了条件

- ①→②→③→登録 で登録でき、③の表示が入力した値と一致する(E2E)
- ③から「修正する」で②へ、「①を修正」で①へ戻れて、入力が消えていない(E2E)
- ②の CTA が「確認へ進む」で、②からは POST されない
- 見出しが `1/3` `2/3` `3/3`
- 任意項目(呼び名・伝達事項)が空のときに「未入力」と出る
- 「小学生にならない生年月日では次へ進めない」が①のまま壊れていない
- 家族連携(招待コード)の導線は変わっていない
