# Plan: 参加可能な時間帯を曜日ごとに設定できるようにする

Issue: [#170](https://github.com/kchan-lab/hoopo/issues/170)
設計の正: docs/REQUIREMENTS.md §3(初回登録②)・§4.2 画面 #2・§4.2-9(家族の設定)・§7(child_availabilities)
/ CLAUDE.md 絶対原則 2(入力負担の最小化)・4(個人情報は最小保持)
関連プラン: child-registration(登録フロー)/ registration-confirm(確認画面)/ child-name-split(同じ「登録項目を変える」変更の前例)

## 目的

いまは参加可能な時間帯が開始・終了の1組しかなく、選んだ全曜日に同じ時間が適用される。
平日の夜と土日の午前で違う家庭が実態を書けないため、曜日ごとに時間を設定できるようにする。
併せて、登録後に直す手段が無い(家族の設定にも管理画面にも編集欄が無い)ので、家族の設定で直せるようにする。
承認者の要望(2026-09-19)。

## 方針

```
[入力] 参加可能な曜日(複数選択)
       [日][月][火][水][木][金][土]

       参加できる時間帯
        日   [09:00] 〜 [12:00]      ← 選んだ曜日だけ行が出る
        土   [09:00] 〜 [12:00]
        ☑ すべての曜日に同じ時間を使う
       ふだん参加できる時間の目安です。日によって違っても大丈夫です
       (その月の参加予定はあとで提出します)

[保存] child_availabilities に (child_id, weekday, start_time, end_time) を曜日ごとに1行。
       テーブルは変更しない(一意制約が (child_id, weekday, start_time) なので複数枠を持てる)

[編集] 家族の設定のお子さんの行で、曜日と時間を直せる。保存はその子の枠をまるごと差し替える
```

### 設計判断

1. **曜日を選ぶと、その曜日の行が下に出る形にする**(承認者の決定 2026-09-19)。
   曜日と時間の対応が画面から素直に読める。
   退けた案: 「枠(曜日の複数選択 + 時間)を追加していく」形。平日夜 / 土午前のような
   実際のパターンには近いが、どの曜日が何時なのかを読み取るのに頭を使う。
2. **曜日を選んだ時点で 09:00〜12:00 を入れておく。** いまと同じく何も触らずに次へ進めるので、
   入力負担は増えない(絶対原則2)。曜日を外したらその行は消し、選び直したら既定値に戻す
   (消したつもりの時間が残ると、確認画面で見たときに驚く)。
3. **「すべての曜日に同じ時間を使う」を既定で入にする。** いまの挙動(全曜日に同じ時間)が既定のまま
   保たれる。1か所直すと全曜日に反映されるので、全部同じ家庭の操作は今と変わらない。
   外したときだけ曜日ごとに別の時間を入れられる。
4. **「毎回この時間どおりでなくてよい」を画面に書く**(承認者の指摘 2026-09-19)。
   厳密な約束だと受け取られると、書くのをためらったり実際より広く書いたりする。
   ただし「守らなくてよい」と直接は書かない。**目安であること**と、**日ごとの都合は参加予定で伝える**
   という次の導線を示す。文言は `@hoopo/api/shared` の定数に置き、登録②と家族の設定で同じものを使う。
5. **兄弟全員に同じ枠を入れる挙動は変えない。** 初回登録では②の入力を全員に適用している
   (`registration.ts:143`)。ここを子ごとに分けると入力が兄弟の数だけ増えるので、絶対原則2 に反する。
   子ごとに違う場合は家族の設定で直す(設計判断6)。
6. **編集は「その子の枠をまるごと差し替える」**(delete → insert)。差分更新にすると、曜日を外したのか
   時間だけ直したのかを判定する必要があり、画面と DB の状態が食い違う余地が増える。
   枠は最大 7 行・順序に意味が無いので、作り直しても失うものが無い。
7. **コーチ側(部員管理)は表示のままにする。** 入力した本人が直せれば足りる。
   部員詳細はすでに複数枠を「曜日 開始〜終了 / …」で出せるので変更不要。
8. **マイグレーションは無い。** `child_availabilities` の一意制約は `(child_id, weekday, start_time)` で、
   同じ曜日に複数の枠を持てる形にすでになっている。列の追加も削除もしない。

## 影響する箇所(調査済み)

- packages/api: `registration-shared.ts`(`RegistrationInput` の `weekdays`/`startTime`/`endTime` を枠の配列へ、
  `ChildPatch` に枠を追加、目安の文言を定数化)、`registration.ts`(登録時の insert・`applyChildPatch` に
  枠の差し替え・家族の設定の取得に枠を含める)
- apps/portal: `register/register-form.tsx`(②の入力・③の確認)、`family/child-edit.tsx`(表示と編集)、
  `globals.css`(曜日ごとの行のレイアウト)
- apps/admin: 変更なし(`member-table.tsx` はすでに複数枠を表示できる)
- packages/db: 変更なし
- docs: REQUIREMENTS §3(登録②の入力項目)・§4.2-9(家族の設定で直せる項目)
- test: Unit(枠の検証)、Integration(登録で枠の数だけ行が入る・編集で差し替わる)、E2E(曜日ごとに違う時間で登録 →
  部員詳細に両方出る → 家族の設定で直す)

## 完了条件

- 登録②で曜日を選ぶと、その曜日の行が出て、曜日ごとに違う時間を入れられる(E2E)
- 「すべての曜日に同じ時間を使う」が既定で入で、1か所直すと全曜日に反映される(E2E)
- 何も触らずに次へ進むと、いまと同じく全曜日 09:00〜12:00 で登録される(Integration)
- 登録③の確認画面に曜日ごとの時間が並ぶ(E2E)
- 時間帯の欄の下に、目安であることと参加予定への導線を示す文言が出る(登録②・家族の設定の両方)
- 家族の設定でお子さんごとに曜日と時間を直せて、再表示しても保たれる(E2E / Integration)
- 開始 >= 終了、曜日 0 件はサーバーが 400 で文言を返す(Unit / Integration)
- 管理画面の部員詳細に、曜日ごとの違う時間がそのまま並ぶ(E2E)
- `packages/db` に差分が無い(マイグレーション無し)
