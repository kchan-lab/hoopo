# Plan: 中学1年生を登録できるようにし、卒団を手動にする

Issue: [#187](https://github.com/kchan-lab/hoopo/issues/187)
設計の正: docs/REQUIREMENTS.md §3(初回登録)・§5.2(部員管理・年度更新)・§7(children / 年度更新)
/ CLAUDE.md 絶対原則 2・4・7
関連プラン: child-birthdate-height(生年月日から学年を出す)/ year-rollover(年度更新)/ member-deletion(卒団後の削除)

## 目的

このチームには**例外として中学1年生が在籍している**。いま学年は小学1〜6年に限定していて、
中1の子は生年月日を入れた時点で弾かれ、登録できない。承認者の申告(2026-09-19)。

## 方針

```
[学年]   1〜7。7 は「中学1年生」。1〜6 はこれまでどおり「小学N年生」

[年度更新]  全員 学年+1(7 は上限なので据え置き)。**自動の卒団アーカイブはしない**
            小6 → 中1 に上がる。中1 はそのまま残る

[卒団]     コーチが部員管理から1人ずつ「卒団させる」。二段階確認 + 実行ログ
```

### 設計判断

1. **学年を 7 まで広げ、7 を「中学1年生」とする**。数字が連続するので、並び順(学年の降順)も
   DB のカラムもそのまま使える。退けた案: 中学生を別のフラグで持つ(学年と二重管理になる)。
2. **年度更新から自動の卒団アーカイブを外す**(承認者の決定 2026-09-19)。
   中1を自動で卒団させたくない、というのが出発点。かといって「小6は自動アーカイブ、中1だけ残す」は
   成立しない。**アーカイブを戻す導線が無い**(`members.ts:141`「復帰 UI は作らない」)ため、
   中1へ上がって続ける子が4月に消えて戻せなくなる。
   毎年4月に卒団する子を手で選ぶ手間が増えるのは**承認者が許容**している。
3. **代わりに部員管理へ「卒団させる」を足す**。破壊的操作なので、既存の「卒団した部員のデータを削除」と
   同じ作法(行内の二段階確認 + `audit_logs` への実行ログ)にそろえる。
4. **学年の表示は共通関数にする**。「小学N年生」がポータル(3か所)と管理画面に散っている。
   `gradeLabel(grade)`(小学4年生 / 中学1年生)と、一覧のピル用の短い形
   `gradeShortLabel(grade)`(4年 / 中1)を `grade-shared.ts` に置く。
   表示の揺れを1か所で直せるようにする。
5. **生年月日の検証の文言を直す**。「小学生の生年月日を入力してください」は実態と合わなくなる。
   受け付ける範囲が分かる言い方にする(portal の入力中ヒントと admin の行編集も同じ文言)。
6. **年度更新の取り消しはそのまま**。snapshot は学年とアーカイブ状態を持っているので、
   アーカイブしなくなっても復元の仕組みは変えなくてよい。確認と結果の文言だけ直す。
7. **マイグレーションはしない**。`children.grade` は smallint で、7 を入れるのに変更は要らない。
   **ただし DB 側に学年の CHECK 制約があれば直す**(実装前に `packages/db/drizzle` を確認すること)。
