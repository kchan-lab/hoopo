# Plan: 参加予定の提出に確認画面を挟む

Issue: [#176](https://github.com/kchan-lab/hoopo/issues/176)
設計の正: docs/REQUIREMENTS.md §4.2-6(参加予定の提出)/ CLAUDE.md 絶対原則 2(保護者の操作負担を最小に)
関連プラン: registration-confirm(登録③の確認画面。作りの前例)/ attendance-submission-state(#145・#154)

## 目的

いま「この内容で提出する」を押すと、確認なしにその場で確定する。カレンダーのタップは
押すたびに回答が巡回する作りなので、誤タップに気づかないまま提出しうる。提出の前に
内容を見せて、特に**未回答の日**に気づけるようにする。承認者の要望(2026-09-19)。

## 方針

```
[編集]  これまでどおり。CTA「この内容で提出する」を押すと確定せず、確認へ切り替わる

[確認]  ‹ 参加予定の確認
        ⚠ 未回答が 2 日あります        ← 未回答が0件なら出さない
        9/6(土) 09:00〜12:00   参加
        9/7(日) 09:00〜12:00   未回答   ← 行を強調
        9/13(土) 13:00〜15:00  欠席
        ...
        [この内容で提出する]
        [修正する]                     ← 編集へ戻る。回答は消えない
```

### 設計判断

1. **同じ画面の表示切替にする**(モーダルにしない)。月の練習は10件を超えることがあり、
   ダイアログに入れると二重スクロールになって未回答を見落とす。登録③(registration-confirm)と
   同じ「state はそのまま、表示だけ切り替える」作りにそろえる。
   退けた案: 件数の要約だけをダイアログに出す。手数は最小だが、**どの日が未回答か**が分からず
   今回の目的を満たさない。
2. **その月の全部を日付順に見せる**(変更した日だけにしない)。主目的は未回答に気づくことで、
   変更分だけだと「触っていないから未回答のまま」の日が出てこない(#154 と同じ関心事)。
3. **未回答は二段で強調する**: 確認の先頭に「未回答が N 日あります」を出し、該当行自体も
   目立たせる(左の色帯 + 「未回答」の字)。件数だけだと直しに戻る手がかりにならず、
   行だけだと一覧が長いときに埋もれる。**未回答が 0 件なら先頭の警告は出さない**。
4. **未回答のままでも提出できる**。現状の仕様(未回答は行を持たない)を変えない。
   全部埋めないと出せない作りにすると、決まっていない日があるだけで提出できなくなり、
   コーチ側の提出率が下がる。警告は出すが止めはしない。
5. **API 契約は変えない**。確認は画面の中の段で、`PUT /api/attendance` はそのまま。
   「下書き」を DB に持たない(絶対原則4・状態はこれまでどおりローカル)。
6. **確認画面では回答を変えられない**。その場で直せるようにすると編集画面と二重になる。
   直すときは「修正する」で編集へ戻る(入力は state に残るので消えない)。

- apps/portal: `attendance/attendance-editor.tsx`(mode の追加・確認の表示・CTA の役割変更)、
  `globals.css`(確認行と未回答の強調)
- packages/api: `attendances-shared.ts` に「未回答の件数」を数える純関数が要るなら足す
  (`submissionState` は既にこの件数を受け取っているので、数え方をそろえる)
- apps/admin: 変更なし
- packages/db: 変更なし(マイグレーション無し)
- docs: REQUIREMENTS §4.2-6

## 完了条件

- 「この内容で提出する」で確定せず、確認の表示に切り替わる(E2E)
- 確認にその月の全練習が日付順に出て、未回答の行が見て分かる(E2E)
- 未回答があるときだけ「未回答が N 日あります」が出る(Unit / E2E)
- 「修正する」で編集に戻り、回答が消えていない(E2E)
- 確認から提出すると、これまでどおり保存され「提出しました」が出る(E2E / Integration)
- 未回答のままでも提出できる(E2E)
- `PUT /api/attendance` の契約が変わっていない(Integration が無改変で通る)
