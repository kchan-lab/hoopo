# Plan: お子さんの名前を姓と名に分けて保持する

Issue: [#155](https://github.com/kchan-lab/hoopo/issues/155)
設計の正: docs/REQUIREMENTS.md §3(初回登録)・§4.2-7(名簿)・§4.2-9(家族の設定)・§5.2(部員管理)・§7(children)/ CLAUDE.md 絶対原則 2・4
関連プラン: child-registration(登録フロー)/ child-birthdate-height(同じ「登録項目を増やす」変更の前例)

## 目的

`children.name`(フルネーム 1 本)を姓と名に分け、姓での並べ替えや集計をできるようにする。
承認者の要望(2026-09-14)。**本番に部員データは 0 件**なので、移行を考えずに作り替える。

## 方針

```
[入力]  姓(粉浜)+ 姓のよみ(こはま)+ 名(太郎)+ 名のよみ(たろう)  ← 4 欄。すべて必須
        呼び名(ひらがな)はこれまでどおり(任意。練習で呼ばれる通称)

[保存]  children.family_name / given_name / family_name_kana / given_name_kana
        (4 つとも必須)。name 列は廃止

[表示]  フルネーム = 姓 + " " + 名(全角スペースは使わない)。
        名簿・出欠・月謝・編成・予定表画像・LINE 文面はこれまでどおりフルネーム(漢字)で出す
        頭文字アバターは姓の先頭 1 文字

[並び順] 名簿・部員管理は 学年(降順)→ 姓のよみ → 名のよみ(= 五十音順)
```

### 設計判断

1. **姓・名の 2 列に置き換え、`name` 列は残さない**: 本番のデータが 0 件で移行の必要がなく、
   フルネームは表示時に組み立てれば足りる。両方を持つと不整合の余地が生まれる。
   退けた案: `name` を残して姓・名を追加(二重管理になり、どちらが正か曖昧になる)。
2. **姓・名それぞれの読み(ひらがな)を必須で持つ**: 名簿を五十音順に並べるには読みが要る。
   入力が 2 欄増えるのは絶対原則 2(入力負担の最小化)とぶつかるが、初回登録の 1 回だけであり、
   五十音順の名簿という運用上の価値が上回ると判断した。承認者の決定(2026-09-15。
   2026-09-14 の「読みは持たない」を撤回)。
   `nickname_kana`(呼び名)は残す: 練習で呼ばれる通称であり、名の読みとは別物。
   一覧(名簿・部員管理・出欠・月謝・編成)には読みを出さない: 1 行の情報量が増えて一覧性が落ちるため、
   並べ替えのためだけに持つ。ただし家族の設定と部員管理の編集画面では、入力した値を確かめられるよう
   読みも表示する。
3. **フルネームの組み立ては共通関数に寄せる**: `fullName({ familyName, givenName })` を
   `@hoopo/api/shared` に置き、画面・予定表画像・LINE 文面すべてがこれを使う。
   区切りは半角スペース 1 つ。表示の揺れを 1 か所で直せるようにする。
4. **並び順は DB 側で `grade desc, family_name_kana, given_name_kana`**: 既存の
   `orderBy(desc(grade), asc(name))` を置き換える。読みはひらがなだけに検証で限定しているので、
   Postgres の既定の照合順序でもそのまま五十音順になる(漢字で並べると読みと食い違う)。
5. **マイグレーションは追加 → 置換の 1 本で行う**(0011): 列を 4 つ(姓・名・それぞれの読み)
   追加し、既存行を埋めてから NOT NULL 制約を付け、`name` を削除する。姓・名は `name` を
   空白で分割して埋められるが、読みは `name` からは作れないので、ローカル/stg の seed 由来の
   行だけ固定値で埋める(それ以外は `ふめい`)。本番はデータが 0 件であることを前提にするため、
   **適用前に stg / prod の children 件数が 0 であることを確認する**(手順は task.md)。
   もし 0 でなければ、姓に全体を入れて名を空にする移行に切り替える(その判断は実行者が行う)。
6. **入力欄の並びは「姓 → 姓のよみ → 名 → 名のよみ → 呼び名」**: 記入の自然な順に合わせ、
   漢字とその読みを隣り合わせにする。4 つとも必須で、それぞれ 25 文字以内
   (従来の 50 文字をフルネーム基準から 1 項目基準に直す)。読みの欄には placeholder
   (こはま / たろう)を置いて、ひらがなで書くものだと分かるようにする。
7. **Sub-issue には割らない**: 触る範囲は広いが、1 つの関心事(名前の持ち方)であり、
   API と画面を別 PR にすると中間状態でビルドが壊れる。1 本の PR で通す。
