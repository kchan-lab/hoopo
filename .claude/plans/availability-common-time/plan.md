# Plan: 参加できる時間帯を、曜日未選択でも入力できる形に直す

Issue: [#179](https://github.com/kchan-lab/hoopo/issues/179)
設計の正: docs/REQUIREMENTS.md §3(初回登録②)・§4.2-9(家族の設定)/ CLAUDE.md 絶対原則 2
前の設計: `.claude/plans/child-availability-slots/plan.md`(#170)。**その設計判断2・3 を今回の形に改める**

## 目的

#170 で入れた見せ方の破綻を直す。承認者の指摘(2026-09-19)。
曜日を1つも選んでいないのに「すべての曜日に同じ時間を使う」が出るのは意味が通らない。
チェックが入っているのに曜日ごとに直せるのも、どちらが効くのか分からない。

## 方針

```
【曜日未選択】                     ← チェックボックスは出さない
参加できる時間帯
  [09:00] 〜 [12:00]
  普段参加できる時間の目安です…

【日・土を選択 / チェックON】       ← 共通の1組だけ。曜日ごとの行は出さない
参加できる時間帯
  [09:00] 〜 [12:00]
  ☑ すべての曜日に同じ時間を使う
  日・土 に同じ時間を使います

【チェックOFF】                    ← ここで初めて曜日ごとの行が出る
参加できる時間帯
  日  [09:00] 〜 [12:00]
  土  [13:00] 〜 [15:00]
  ☐ すべての曜日に同じ時間を使う
```

### 設計判断

1. **時間の欄は常に出す**(曜日を選ぶ前から)。「上で曜日を選ぶと…」という案内だけを置くと、
   何を入れる欄なのかが分からないまま画面が空く。既定値(09:00〜12:00)が見えていれば、
   触らなくてよいことも伝わる。**#170 の設計判断2 を改める**。
2. **チェックボックスは曜日を1つ以上選んでいるときだけ出す**。曜日が無い状態の
   「すべての曜日」は指すものが無い(承認者の指摘1)。
3. **チェック中は共通の1組だけを出し、曜日ごとの行は出さない**(承認者が選択)。
   「同じ時間を使う」と言いながら曜日ごとに直せるのは矛盾で、無効化して並べると
   同じ時刻が上下に重複する。行を出さないのが一番短く、直す場所も1か所に定まる。
   **#170 の設計判断3 を改める**(既定でチェックが入っているのは変えない)。
4. **状態は「選んだ曜日」「共通の時間」「曜日ごとの時間」の3つに分ける**。
   #170 は曜日ごとの配列だけを持っていたため、曜日が0件のときに時間の置き場が無かった。
   送信する値は3つから組み立てる(チェック中は全曜日に共通の時間、外していれば曜日ごとの時間)。
5. **チェックを外したときは、そのときの共通の時間を曜日ごとの初期値にする**。
   外した瞬間に値が変わって見えると驚く。逆に入れ直したら共通の時間に戻る。
6. **保存される値の形は変えない**。API も DB もそのまま(`availabilities` の配列)。
   何も触らずに進めば、これまでどおり選んだ全曜日が 09:00〜12:00 で登録される。
7. **家族の設定の編集も同じ形にそろえる**。登録と編集で見せ方が違うと迷う。
   既存データを開いたときは、全曜日の時間が同じならチェックを入れた状態、違えば外した状態で始める
   (いまの `allSameTime` の判定をそのまま使う)。

## 完了条件

- 曜日未選択で、時間の欄が出ていてチェックボックスが出ていない
- 曜日を選ぶとチェックボックスが出て、既定で入っている
- チェック中は曜日ごとの行が出ない。外すと出て、個別に直せる
- 外した直後の各行の値が、直前の共通の時間になっている
- 何も触らずに進むと、選んだ全曜日が 09:00〜12:00 で登録される(Integration)
- 家族の設定でも同じ見せ方で、既存の値によって初期のチェック状態が決まる(E2E)
- API・DB の変更が無い
